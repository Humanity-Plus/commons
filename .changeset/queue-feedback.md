Three PR-queue runs' worth of feedback: cheaper small reviews, a shipped bundle builder, and a review record that can describe a merged tree.

- **Small reviews cost less.** A test file counts with the source file it tests toward the light tier's two files. At the medium tier `intent`, `preflight`, and `primitives` may share one agent, each with its own output; `seams` and `blast-radius` keep their own. The primitives lens is skipped on test-only and docs-only changes.
- **`build-bundle.sh`** writes the lenses' materials to `review-report/bundle/`, one file per section (`common.md`, `diff.md`, `conventions.md`, `intent.md`, `primitives.md`), reading the repo's rules from the base branch. It replaces the single bundle file, which reached 187 KB on a repo with a large primitives map. Fence lines carry a per-run token so diff or PR text cannot pose as a trusted block, and a `--spec` file must be tracked or sit under `review-report/`. File names are passed to git as literal paths, never as pathspec patterns.
- **`meta.reviewedSha`** records the commit the lenses read when it is not the PR's pushed head, as when a loop merges the base branch in first. The fixer's freshness check and the workspace reset follow it. For such a review the report and the published body link no line, and `publish.ts` refuses to post unless you push the merge and re-run the review, or pass `--body-only`.
- **`check-clean.sh` changes behaviour.** Files written into `review-report/` during a check are merged back into the restored folder; it stops with exit 2, deleting no file, when a path exists on both sides, cannot be moved, or `review-report` came back as something other than a folder. It finds `review-report/` at the repository root from any folder. It exits 3 when a passing check changed the working tree, by status or by content, which is how a stale generated file shows. Treat 3 as "regenerate and commit", not as a failed gate, and run whole-repo checks before the lenses start.
- **`reset-workspace.sh`** archives the resolution log with its findings (`resolution-<label>.md`), and a log with no findings beside it as `resolution-old.md`. `jq` is needed to recognise a findings file that still describes the checkout.
- **Stricter reports.** A severity is trimmed and lower-cased, and `nit` is read as `nitpick`; any other value, or a missing severity, is refused by `render.ts` and `publish.ts` with the finding named. An older saved report with such a value needs that field fixed before it renders again. The compact index carries each finding's lens.
- Lenses may write probe files under `review-report/lenses/probes/`; the review copies a referenced probe into its record. A PR body's mutation table that matches the fix phase's ledger is spot-checked, not re-run in full.
- `fix-the-class` names the fallback for data already stored under an old rule: an always-check entry and a backfill issue. The verify-skill Doctor checks that the instance was launched from the commit being driven and that edits reach it.
